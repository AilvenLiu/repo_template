### Task-1-5: bin/agent-build Refactored to Use build_system Axis

Refactored bin/agent-build to dispatch by project_profile.build_system instead of legacy project_type.

**Key Changes:**

1. **Renamed project_type() to get_build_system()**:
   - Reads `project_profile.build_system` from `.ai/project.yml` first
   - Falls back to legacy `project_type` field with mapping:
     - `python` → `poetry`
     - `cpp` → `cmake`
   - Defaults to `poetry` if no config file exists

2. **Updated Function Names**:
   - `python_setup()` → `poetry_setup()`
   - `python_compile()` → `poetry_compile()`
   - `python_test()` → `poetry_test()`
   - `python_doctor()` → `poetry_doctor()`
   - `cpp_*()` → `cmake_*()`

3. **Updated Dispatch Logic**:
   - Changed from `case "$(project_type)"` to `case "$(get_build_system)"`
   - Dispatch on build_system values: `poetry`, `cmake`, `scikit-build`, `bazel`, `mixed`

4. **Added Stub Branches**:
   - `scikit_build_stub()`: Prints "not yet implemented" message and exits 1
   - `bazel_stub()`: Prints "not yet implemented" message and exits 1
   - `mixed_stub()`: Prints "not yet implemented" message and exits 1
   - All stubs reference Phase 2 and point to ADR documentation

5. **Maintained Backward Compatibility**:
   - Legacy `project_type: python` → uses poetry branch
   - Legacy `project_type: cpp` → uses cmake branch
   - Existing Python and C++ projects work identically
