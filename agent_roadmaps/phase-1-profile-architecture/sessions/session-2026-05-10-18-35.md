### Task-1-3: Constraint Loader Refactored

Refactored [.ai/scripts/session_init.py](../../../.ai/scripts/session_init.py) to load constraints by profile axes instead of binary `project_type`.

**Key Changes:**

1. **Import Changes**: Updated imports from `project_type` to `project_profile`
   - Now imports `Language`, `ProjectProfile`, and `detect` from `project_profile`
   - Maintains backward compatibility through the shim

2. **resolve_constraints() Refactor**:
   - Changed signature from `project_type: ProjectType` to `profile: ProjectProfile`
   - Replaced `if/elif` with independent `if` blocks to support hybrid profiles
   - Uses `profile.has_language(Language.PYTHON)` and `profile.has_language(Language.CPP)`
   - Moved `exts_seen` calculation outside language blocks for efficiency
   - Supports loading both Python and C++ constraints for hybrid projects

3. **write_session_state() Update**:
   - Changed signature from `project_type: ProjectType` to `profile: ProjectProfile`
   - Session state now stores `project_profile` dict instead of `project_type` string
   - Uses `profile.to_dict()` for serialization

4. **run_init() Update**:
   - Calls `detect()` which returns `ProjectProfile` (or `None` for unknown)
   - Falls back to `legacy_project_type_to_profile("python")` for unknown projects
   - Displays primary language for backward-compatible output format
   - Passes `profile` to `resolve_constraints()` and `write_session_state()`

## Decisions Made

1. **Additive Composition**: Changed from `if/elif` to independent `if` blocks so hybrid profiles can load constraints from multiple languages simultaneously.

2. **Session State Format**: Session state now stores the full `project_profile` dict instead of just the `project_type` string. This provides richer information for future tooling while maintaining backward compatibility through the detection shim.

3. **Output Format**: Kept the "Project type: PYTHON" output format for backward compatibility, displaying the primary language from the profile.
