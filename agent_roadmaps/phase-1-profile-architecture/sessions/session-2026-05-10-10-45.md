### Task-1-1: ADR Drafted

Created [.ai/adr/0001-project-profile.md](../../../.ai/adr/0001-project-profile.md) documenting the new composable `project_profile` schema.

**ADR Contents:**
- **Context**: Explains why the binary `project_type` enum cannot express hybrid AI infra projects (TVM, MLC-LLM, FlashInfer)
- **Decision**: Replace with composable profile with 6 axes:
  - `language`: [python, cpp] (can be multiple)
  - `build_system`: poetry | cmake | scikit-build | bazel | mixed
  - `bindings`: none | nanobind | pybind11 | tvm-ffi | ctypes
  - `distribution`: none | pypi | conda | system | header-only
  - `hardware_targets`: [cpu, cuda, rocm, metal, vulkan]
  - `external_dependencies`: none | system_cuda | system_nvidia | vendored
- **Worked Examples**: Three complete examples:
  1. Pure Python (legacy compatible)
  2. Pure C++/CUDA (legacy compatible)
  3. Hybrid TVM-shaped project (Phase 2)
- **Backward Compatibility**: Explicit mapping table and shim implementation strategy
- **Consequences**: Positive (unlocks Phase 2, composable), Negative (migration complexity), Risks (with mitigations)
- **Alternatives Considered**: Four alternatives rejected with rationale

## Decisions Made

1. **Schema Design**: Six-axis composition (language, build_system, bindings, distribution, hardware_targets, external_dependencies)
2. **Constraint Loading**: Additive composition - hybrid projects get both Python and C++ constraints
3. **Build Dispatch**: Driven by `build_system` axis, not language
4. **Capability Audit**: New `when:` selector syntax (e.g., `when: language=python`)
5. **Backward Compat Strategy**: Shim at old `project_type.py` path that re-exports new API plus `legacy_project_type_to_profile()` helper
